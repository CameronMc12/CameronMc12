# DESIGN.md — the profile's grammar

Everything on `github.com/CameronMc12` is generated by `scripts/`. This file is
the contract they are written against. Change a token here and re-run
`python3 scripts/render_all.py`; never hardcode a colour in a renderer.

## 0. How to use this file

Read §1–§6 before touching a renderer. §9 is the running record of what Cameron
has ruled on — it wins over anything else here.

## 1. Direction

**Matrix mainframe.** Near-black ground, one phosphor-green accent, mono labels,
generous negative space, real data everywhere.

Explicitly NOT a landing page. Every section is a compact band you glance at:
one small caps label on the left, its context on the right, then the content.
No section headlines, no eyebrow rules, no hero copy per section. An earlier
pass gave every section an eyebrow plus a 34px headline; it cost ~90px each and
made the whole page read as a pitch deck. That pattern is banned.

## 2. Platform

Authored at **846px**, which is GitHub's profile README column at a 1512px
viewport (it is 766px at 1200px). Everything scales down from there, so the gate
in `shoot.py` renders at 846 rather than 1:1 — anything that only reads at full
size does not read.

**Dark only.** There is no light pair. Digital rain and phosphor only work
against black and the page is one continuous dark surface; a reader in GitHub's
light theme gets a deliberate dark page, the way a photograph does not invert.

GitHub's sandbox blocks external fonts — so the display face is really whatever
`system-ui` resolves to. Every size is chosen to survive that.

## 5. Motion

Reveals play **once and freeze** (`animation-fill-mode: both`, no
`repeatCount`). The only things that loop are textures: the rain, the blip on
the "taking on work" dot, and the nudge on a button arrow.

**Never rest an element at `opacity:0`.** `both` back-fills the from-state
during the delay, so the invisible state belongs in the keyframe and the base
style must be the visible one. Chromium does not run animations in an offscreen
`<img>`-embedded SVG; anything resting at zero can stay invisible for good.

**Never put a CSS `transform` on an element that also has a `transform`
attribute.** The CSS one replaces it outright rather than composing, so the
element teleports to the origin the moment the animation starts. Position on an
outer `<g>`, animate an inner one.

**There is no hover.** Pointer events never reach an `<img>`-embedded SVG, so
`:hover`, transitions and cursor changes are all inert. A looping arrow nudge is
the only honest way to say "this goes somewhere" inside an image.

## 7. Colour discipline

Contrast is spent, not sprayed. At most ONE thing per section gets full phosphor:

- commits → the total, and the top of the cell ramp
- stack → TypeScript, the top language
- momentum → the line and its head
- working hours → the peak hour spoke and the peak figure
- weekly rhythm → the peak day only
- shipped → the most recent dot
- contact → the email pill
- buttons → GitHub is filled; the rest are outlined

## 9. Rulings

- **2026-08-27 — Matrix green is the whole page**, not one panel. The earlier
  build used lime `#E4F222` with green quarantined to the rain; Cameron chose
  the film phosphor as the single accent throughout.
- **2026-08-27 — No landing-page chrome.** No section headlines, no eyebrows,
  no multi-paragraph copy. A visitor should be able to scan the page in about
  ten seconds.
- **2026-08-27 — Private repo NAMES never appear.** They are client work.
  Aggregate bytes and hour buckets are fine; the project list is hand-written in
  `data/identity.json` and is Cameron's call, not the API's.
- **2026-08-27 — Measure before writing the copy.** The working-hours section
  was mocked as a night owl peaking at 22:00. The real timestamps say 93%
  between 08:00 and 18:00, peak at midday, nothing after 21:00. The measurement
  rewrote the section.
